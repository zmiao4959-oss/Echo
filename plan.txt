0.2 新产品定义
Echo 是一个带记忆系统的 Android AI 生活伙伴。
它不是普通聊天机器人，也不是单纯闹钟，而是一个可以：
听用户记录生活
把碎片整理成日记
把未来安排成规划
在合适时间主动问候
从过去记录中唤起回忆
基于长期记忆形成陪伴感
的私人生活智能体。
一句话定义：
Echo 是一个会记住你生活、帮你整理日记、规划未来，并在合适时间主动与你交互的 Android AI 伙伴。

1. 产品总结构
1.1 底部导航
重构为 4 个主入口：
今日 / 日记 / 规划 / 回忆
设置、头像、背景、API Key、TTS 开关等放到右上角头像入口。
1.2 四个入口职责
今日
职责：记录当下。
今日页是 Echo 的主入口，用户在这里随手记录生活片段，也可以和 Echo 对话。
今日页包括：
日期
天气条
今日状态卡
生活片段记录入口
小爪/原对话能力卡片
今日片段列表
AI 整理预览
右下角语音悬浮按钮
原来的聊天功能不要删除，改造成今日页里的“小爪对话卡片”。
日记
职责：整理一天。
日记页展示 AI 生成的每日整理结果。
日记页包括：
今日精选日记卡
手动生成日记按钮
历史日记列表
月份筛选
标签筛选
情绪筛选
阅读全文入口
朗读日记入口
规划
职责：安排未来 + 主动交互。
规划页不是单纯提醒列表，而是 Echo 的主动交互系统。
规划包括三类：
1.任务提醒
例如：明天 9 点提醒我检查计算任务。
2.主动问候
例如：每天晚上 11 点问我今天过得怎么样。
3.回忆触发
例如：每周日晚上总结这一周的生活记录。
规划页包括：
今日规划
未来规划
主动问候
回忆触发
自动日记整理开关
每条规划的启用/停用/删除/测试播放
回忆
职责：唤起过去。
回忆页不是简单历史列表，而是 Echo 的记忆系统界面。
回忆页包括：
随机记忆卡片
值得保留的话
按关键词搜索
按情绪搜索
按人物/主题搜索
长期记忆
回忆触发历史
“那天的你”卡片

2. 设计原则
2.1 技术原则
当前项目是 XML UI，不要强行切 Jetpack Compose。
第一阶段保持：
XML + RecyclerView + ViewModel + Repository + 文件存储 + SharedPreferences
不要引入 Room，除非后续单独开数据库迁移任务。
原因：
当前项目已有文件式持久化
workspace 已经依赖 notes.md / memory.md
Claude Code 在现有架构上增量开发更稳
现在首要目标是产品重构，不是底层数据库重构
2.2 视觉原则
结构使用 Material 3，气质使用温柔日记风。
关键词：
Echo
温暖
安静
米白背景
青绿色点缀
圆角卡片
轻阴影
手账感
日记感
水彩插画感
克制
不要科技感大屏
不要聊天软件感过重
2.3 智能体原则
Echo 的 AI 不再只是聊天模型，而是四种身份贯穿全局：
今日：倾听者
日记：整理者
规划：提醒者
回忆：陪伴者
不要单独做“AI 页面”。
AI 要渗透到四个页面里。
2.4 定时系统原则
原有定时提醒功能必须保留，并升级为“规划系统”。
规划系统中的事件分为：
task_reminder       任务提醒
companion_checkin   主动问候
memory_trigger      回忆触发
auto_diary          自动日记整理
不同类型触发行为不同：
任务提醒：
默认允许自动语音播报。

主动问候：
默认只弹通知。
用户可单独设置是否自动播报。

回忆触发：
默认弹通知 + 可点开查看。
用户可设置是否自动播报。

自动日记：
默认后台生成，不主动播放。
生成后可通知用户。

5. 四层记忆系统
新版 Echo 记忆系统先按四层实现。
5.1 第一层：原始记录 LifeRecord
含义：用户每天随手留下的生活片段。
来源：
用户手动输入
语音识别文本
对话中用户主动说“记一下”
主动问候后用户的回答
数据类建议：
data class LifeRecord(
    val id: String,
    val createdAt: Long,
    val date: String,              // yyyy-MM-dd
    val content: String,
    val source: String,            // text, voice, chat, checkin
    val mood: String? = null,
    val tags: List<String> = emptyList(),
    val importance: Int = 1,       // 1-5
    val linkedPlanId: String? = null,
    val rawConversationId: String? = null
)
5.2 第二层：日记记忆 DailyDiary
含义：AI 根据一天的 LifeRecord 整理出的每日文本。
数据类建议：
data class DailyDiary(
    val id: String,
    val date: String,              // yyyy-MM-dd
    val title: String,
    val summary: String,
    val diaryText: String,
    val mood: String,
    val tags: List<String>,
    val sourceRecordIds: List<String>,
    val createdAt: Long,
    val updatedAt: Long,
    val generatedBy: String = "ai",
    val version: Int = 1
)
5.3 第三层：人物画像 UserProfileMemory
含义：长期偏好、习惯、重要目标。
数据类建议：
data class UserProfileMemory(
    val id: String,
    val key: String,
    val value: String,
    val category: String,          // preference, habit, goal, identity, project, relationship
    val confidence: Float,         // 0.0 - 1.0
    val sourceIds: List<String>,
    val createdAt: Long,
    val updatedAt: Long,
    val enabled: Boolean = true
)
第一阶段不要自动无限写画像，只允许 AI 提议，App 存储前可以先走低风险策略：
明显长期偏好可保存
明显短期情绪不进长期画像
敏感信息不主动保存
用户可以在回忆页管理长期记忆
5.4 第四层：回忆卡片 MemoryCard
含义：值得以后被重新提起的一句话、一段经历、一次转折。
数据类建议：
data class MemoryCard(
    val id: String,
    val createdAt: Long,
    val memoryDate: String,
    val quote: String,
    val note: String,
    val tags: List<String>,
    val mood: String? = null,
    val sourceType: String,        // life_record, diary, chat
    val sourceId: String,
    val pinned: Boolean = false
)

7. Echo system prompt 重构
新增 workspace 文件：
/files/echo/workspace/echo_profile.md
内容包括：
# Echo 角色设定

你是 Echo，一个私人生活记录 AI 伙伴。

你的核心任务不是单纯回答问题，而是帮助用户：
1. 记录生活片段
2. 整理每日经历
3. 形成日记
4. 规划未来提醒和主动问候
5. 从过去记忆中唤起重要片段

## 说话风格

- 温柔
- 克制
- 真诚
- 不说教
- 不强行鼓励
- 不像客服
- 不要过度鸡汤
- 用户表达混乱时，先帮他接住情绪，再轻轻整理结构

## 四种身份

今日：倾听者
日记：整理者
规划：提醒者
回忆：陪伴者

## 生活记录规则

当用户表达明显生活片段、情绪、经历、项目进展、想法转折时，可以调用 create_life_record。
不要把所有闲聊都保存。
保存前后的回复要自然，不要机械。

## 规划规则

当用户表达未来时间、提醒、问候、自动整理、回顾需求时，可以调用 create_plan。
任务提醒可以自动播报。
主动问候默认不自动播报，除非用户明确要求。
回忆触发默认通知，不默认强制语音播报。

## 日记规则

日记不是流水账，而是温柔整理用户一天的真实状态。
不要编造用户没说过的事。
可以根据记录提炼主题、情绪和关键词。

## 回忆规则

回忆不是打扰，而是在合适的时候把过去重要的片段带回来。
当前已有 memory.md 可以继续注入，但建议 system prompt 注入顺序改成：
1. Echo 基础人格 echo_profile.md
2. 用户长期画像 memory.md
3. 当前日期、天气、时间
4. 今日 LifeRecord 摘要
5. 最近 DailyDiary 摘要
6. 当前对话上下文

24. 产品方向总结
Echo 的核心不是“它能帮用户做多少事”，而是：
它能不能温柔、稳定、长期地保存用户的生活。
四个入口分别解决四个时间方向：
今日：我现在正在经历什么
日记：我今天到底经历了什么
规划：未来我希望 Echo 什么时候出现
回忆：过去的我留下了什么
原有的定时语音不是被舍弃，而是变成 Echo 的主动出现能力。
原有的记忆系统不是被舍弃，而是升级为四层记忆：
LifeRecord：原始生活片段
DailyDiary：每日整理
UserProfileMemory：长期画像
MemoryCard：值得回看的记忆
最终 Echo 应该像一个安静但可靠的生活伙伴：
你说，它记下
你乱，它整理
你忘，它提醒
你累，它问候
你回头，它把过去递给你
