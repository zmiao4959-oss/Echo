# Echo 人工验收文档

按步骤手动验证核心链路。预期结果基于最新代码（Phase D + D-Fix）。

---

## 1. 首次启动和 LLM 配置

1. 卸载 App 后重新安装（或清除数据）
2. 启动 App → 应看到 Toast 提示"请先配置 LLM"
3. 自动跳转设置页 → 填写 API Base URL、API Key、Model
4. 点击"保存配置" → 返回主页 → 今日页正常显示

**预期**: 配置后主页不再弹 Toast，天气条/问候语正常显示。

---

## 2. 发起普通对话 → 验证流式输出

1. 在今日页点击"进入对话"卡片
2. 输入"你好，介绍一下你自己"
3. 观察回复

**预期**: 文字逐字流式出现（不是一次性跳出来）。回复内容提到 Echo 的人格设定。

---

## 3. 触发工具调用

1. 在对话中输入"帮我查一下上海的天气"
2. 观察过程

**预期**: 
- 看到"正在执行工具调用..."状态提示
- 看到 `get_weather` 工具被调用
- 返回天气结果
- 如果天气 API 失败，对话能优雅降级（不会崩溃）

---

## 4. 记住用户信息 → 验证记忆可见

1. 对话中输入"记住，我叫小明，我在北京工作"
2. 返回个人中心 → 点击"Echo 记住的事"
3. 查看"用户画像"和"长期记忆片段"

**预期**: 
- 用户画像中显示 Echo 记住的信息
- 长期记忆片段显示 MEMORY.md 中的事实
- 每条记忆可编辑、可删除、可禁用

---

## 5. 查看/编辑/删除记忆

1. 在"Echo 记住的事"页面
2. 尝试编辑一条画像记忆 → 弹出编辑框 → 修改后保存
3. 尝试禁用一个画像 → 开关关闭
4. 尝试置顶一个记忆卡片 → 显示 📌
5. 尝试删除一条长期记忆片段

**预期**: 编辑/删除/禁用/置顶都立即生效，页面刷新。

---

## 6. 新建/切换/删除会话

1. 在对话页点击标题栏（带 ▼ 的标题）
2. 进入对话列表页
3. 点击"新对话" → 进入空白对话页
4. 发送一条消息 → 返回列表页 → 新对话出现
5. 长按某对话 → 重命名 → 确认名称已更新
6. 长按某对话 → 删除 → 确认已从列表消失

**预期**: 
- 删除当前对话后，下次进入今日页会创建新对话
- 对话标题不包含 `[Memory Search Results]` 前缀

---

## 7. 创建提醒 → 验证闹钟触发

1. 对话中输入"提醒我明天早上 9 点开会"
2. 或：在规划页点击 FAB → 创建任务提醒
3. 设置 2 分钟后触发（方便验证）

**预期**: 
- 到时间后收到系统通知
- 通知内容为"⏰ 任务标题"和提醒消息
- 通知点击能打开 App

---

## 8. 重启后恢复会话和提醒

1. 在对话中发几条消息
2. 完全退出 App（从最近任务中划掉）
3. 重新打开 App → 点击"进入对话"

**预期**: 
- 之前的对话历史完整保留
- 提醒闹钟在重启后自动恢复（MyApplication 恢复）

---

## 9. 天气失败诊断

1. 断开设备网络
2. 打开设置页 → 点击"保存配置"返回主页
3. 观察主页天气条
4. 进入设置页 → 查看诊断面板

**预期**: 
- 天气获取失败不崩溃（静默失败）
- 诊断面板中"Weather"显示最近失败次数
- 错误信息不包含 API key

---

## 10. TTS 开关与失败提示

1. 设置页中 TTS 对话语音开关 → 关闭
2. 发起对话 → 不应有 TTS 合成提示
3. 开关 → 打开
4. 再次对话 → 应有 TTS 相关日志

**预期**: 开关即时生效。TTS 未配置时对话不报错。

---

## 11. 主题/背景/纹理切换

1. 个人中心 → 选择主题 → 切换为"森林绿"
2. 返回主页 → 确认主题已切换
3. 个人中心 → 页面纹理 → 选一个纹理
4. 个人中心 → 卡片纹理 → 选一个纹理
5. 个人中心 → 卡片形状 → 选"大圆角"

**预期**: 
- 主题/纹理/形状切换后主页自动刷新
- 卡片圆角变化可见
- 重启后设置保留

---

## 12. 诊断面板检查

1. 打开设置页 → 滚动到底部
2. 查看诊断区域

**预期**: 
- LLM: 已配置（显示模型名）
- TTS: 已配置/未配置
- 天气: 城市名 + 状态
- 通知权限: 已授权/未授权
- 精确闹钟: 已授权/未授权
- 最近错误: 显示各服务的失败摘要

---

## 13. D-Fix: 记忆禁用/待确认生效验证

1. 在"Echo 记住的事"中禁用一条用户画像
2. 发起新对话 → 触发搜索 → 观察系统提示
3. 确认被禁用的画像不出现在对话中
4. 在"长期记忆片段"中禁用一个 MEMORY.md 事实（点击"禁用"按钮，确认移到 "🚫 已禁用" 分组）
5. 发起新对话，确认被禁用的事实不出现在搜索结果中

**预期**: 被禁用的画像和 MEMORY.md 事实均不注入系统提示，待确认的记忆卡片不出现在主动回忆中。

## 14. D-Fix: 主动陪伴设置生效验证

1. 设置页 → 关闭"开启主动陪伴"
2. 等待一个陪伴计划触发（或手动调整计划时间）
3. 确认不收到陪伴类通知
4. 设置页 → 打开"开启主动陪伴" → 设置静默时段覆盖当前时间
5. 确认静默时段内不收到陪伴通知

**预期**: 陪伴开关和静默时段即时生效。任务提醒不受陪伴开关影响。

## 15. D-Fix: 对话列表搜索验证

1. 进入对话列表页
2. 在搜索框输入关键词
3. 确认列表实时过滤

**预期**: 按标题和消息内容搜索，清空搜索显示全部。

## 16. D-Fix2: MEMORY.md 权限闭环验证

### 16a. 禁用事实 → 验证不在搜索中出现
1. 在"Echo 记住的事"页面 → "长期记忆片段"区域
2. 确认有一条已确认的事实（在 "✅ 确认的记忆" 分组下）
3. 点击该事实的"禁用"按钮
4. 确认该事实移动到 "🚫 已禁用" 分组
5. 发起新对话，提到该事实的关键词
6. 观察 AI 回复

**预期**: 被禁用的事实不出现在系统提示中，AI 不会引用被禁用的记忆。

### 16b. 重新启用 → 验证恢复可见
1. 在"Echo 记住的事"页面找到刚才禁用的事实（在 "🚫 已禁用" 分组下）
2. 点击"启用"按钮
3. 确认该事实回到 "✅ 确认的记忆" 分组
4. 发起新对话，提到该事实的关键词

**预期**: AI 能够引用恢复的记忆。

### 16c. 待确认事实不注入对话
1. 手动在 MEMORY.md 的 "⏳ 待确认" 区域添加一行（如 `- [2026-06-26 14:30] [other] 测试待确认`）
2. 发起新对话，提到其中的关键词
3. 在"Echo 记住的事"页面确认该事实出现在 "⏳ 待确认" 分组

**预期**: 待确认的事实不出现在 AI 的回应中。

### 16d. remember_user_fact 写入确认区域
1. 对话中输入"记住，我的新手机号是 138xxxx"
2. 检查 MEMORY.md 文件内容

**预期**: 新事实写入 "## ✅ 确认的记忆" 区域，带有时间戳和分类。如果文件之前是旧格式（`## Echo 记住的关于你的事`），自动迁移到新格式。

### 16e. 旧格式 MEMORY.md 兼容性
1. 手动将 MEMORY.md 的 "## ✅ 确认的记忆" 改回 "## Echo 记住的关于你的事"
2. 发起对话，提到其中的事实

**预期**: 旧格式内容被当作已确认处理，AI 可以引用。再次调用 remember_user_fact 后，文件自动迁移到新格式。

**预期**: 显示"🌱 还没有成长记录，开始记录你的生活吧。"，样式温和不报错。

5. 再次进入成长轨迹页

- 类型筛选 Chip 可用（全部 / 生活记录 / 日记 / 记忆卡片 / 周回顾 / 计划 / 画像变更）

## 23. Phase G: 记忆沉淀验证

**预期**:

3. 丢弃一个候选画像 → 再次触发沉淀 → 确认丢弃过的相似画像不重复出现
4. 不调用 LLM 时沉淀仍可运行

## 27. 今日页：记录后微回声验证

1. LLM 已配置时，在今日页输入一条有具体情绪或进展的生活片段并点击“记录”

**预期**：
- 生活片段立即出现在列表中，不等待 LLM
- 页面顶部的单一反馈卡立即切换为“Echo 回声”，先显示“正在回应”状态
- 最迟约 18 秒内替换为一句简短、自然的回应
- 回应不带标题、Markdown、长篇建议或夸张赞美

2. 关闭网络或清空 LLM 配置后再次记录

**预期**：记录仍正常保存，并显示本地兜底回声，不弹错误、不长时间卡住。

3. 离开今日页再返回，点击刚才的生活片段查看详情

**预期**：微回声仍然显示，记录详情中也包含“Echo 回声”。

4. 连续快速保存两条记录，再删除最新一条

**预期**：旧请求不会覆盖新回声；删除后不显示已删除记录的回声，应用不崩溃。

5. 对新生成的回声点击“有共鸣”，离开今日页后再返回

**预期**：“有共鸣”和“不太像我，换一句”两个选项一起隐藏，回声内容保持不变；在 30 分钟新鲜窗口内返回页面时已认可状态仍保留，选项不会重新出现。

6. 对另一条回声点击“不太像我，换一句”

**预期**：卡片先回到“正在回应”，随后原位替换为新回声；不重复刚被拒绝的原句，记录本身不会被重复新增。连续换句直到拒绝记录达到 6 条上限时，下一条本地兜底回声仍应避开当前拒绝列表，不固定回到同一句。

7. 先标记几条“有共鸣”和“不太像我”，再新增一条片段

**预期**：新回声依然只回应当前内容，但逐渐靠近已认可的语气，并避免已拒绝的措辞；断网及纯语音记录时仍能换成不同的本地回声。

## 28. 今日页：今日正在形成验证

1. 清空当天记录后进入今日页

**预期**：“今日正在形成”卡片显示从第一条片段开始的温和引导，不编造主题或情绪。

2. 依次记录“上午开会讨论项目”“下班后跑步半小时”等 2～3 个片段

**预期**：
- 卡片中的片段数量实时增长
- 出现“工作”“运动”等有明确依据的主题
- 阶段性观察随数量变化，不再只是提示“可以生成日记”
- 卡片更新无需等待网络，也不会额外出现 AI 加载状态

3. 记录“项目终于搞定了，特别开心”，或通过对话保存带 mood/tags 的生活记录

**预期**：优先展示记录自带的情绪/标签；没有元数据时，仅对明确情绪用词做轻量识别。

4. 记录两条都包含同一具体短语的片段，如“上午在咖啡馆整理照片”“下午又去了咖啡馆见朋友”

**预期**：主题可显示完整的“咖啡馆”，不出现“啡馆”这类破碎二字词。

5. 删除上述记录

**预期**：数量、主题和情绪随剩余记录立即重算；删空后回到温和引导状态。

## 29. 回忆页：往日回声验证

1. 确保至少有一条 3 天前的生活记录或日记，进入“回忆”页

**预期**：“往日回声”卡片可见，显示“X 天前”和原始日期；同一天多条内容只展示一条有代表性的记录。

2. 准备 7 天前、14 天前或 30 天前的数据

**预期**：优先展示时间节点；同时存在多个节点时优先更久以前的节点，如 30 天前优先于 7 天前。

3. 如果存在往年同月同日的数据，再次进入回忆页

**预期**：周年记录优先，显示“一年前的今天”或“X 年前的今天”。

4. 点击一条日记来源的往日回声

**预期**：打开对应日记详情；点击生活片段来源时显示片段详情，而不是无响应。

5. 对带有 mood 或已保存微回声的生活片段进行回看

**预期**：详情展示真实心情；卡片和详情可显示“当时 Echo 说”，不重新请求 LLM。

6. 同一天反复离开并进入回忆页

**预期**：无周年/节点时的历史回声保持稳定，不因刷新随机跳动；无 3 天以上历史数据时卡片隐藏。

7. 准备含“去世”“自残”“创伤”等明显痛苦内容的旧记录

**预期**：该内容仍可在历史和搜索中找到，但不会被“往日回声”自动带回。

## 30. 聊天页：返回与消息刷新验证

1. 从今日页进入聊天，分别使用系统返回手势和虚拟返回键

**预期**：两种方式都直接离开当前聊天并返回上一页，不穿过历史对话，不退出整个应用。

2. 从对话列表切换到另一段对话，再使用返回手势

**预期**：仍然只退出当前聊天页；再次进入时能够恢复最后选择的对话。

3. 发送会触发工具调用的消息，观察流式回答

**预期**：文字持续更新；工具开始和完成信息能够出现；流式光标在完成后消失，不发生消息停在旧内容或空白的情况。

4. 快速连续发送普通消息并等待回答完成

**预期**：消息不重复、不串位，完成后的内容不会被无意义地反复刷新。

## 31. 今日页：最近 7 天足迹验证

1. 在任意反馈状态下进入今日页，观察问候下方的“最近 7 天”统计卡

**预期**：统计卡始终显示“最近 7 天”以及从六天前到今天的 7 个圆点，不会被微回声或“回来就好”替换；今天标记为“今”，无记录的今天使用主题色描边提示但不制造警告。

2. 当天连续新增两条生活片段

**预期**：今天圆点内显示“2”，右上角片段总数同步增加；删除其中一条后立即回到“1”。

3. 使用包含最近 7 天多日记录的数据进入今日页

**预期**：有记录的日期使用主题色实心圆点，卡片准确显示“X 天 · Y 个片段”。

4. 当前 7 天记录天数多于此前 7 天

**预期**：文案可以显示“比前 7 天多留下 X 天”；只有正向变化会被比较和庆祝。

5. 当前 7 天比此前 7 天更少，或中间有漏记日期

**预期**：不出现“下降”“中断”“归零”或负数，只描述已经留下的积累；零记录时显示“今天写一句也算开始”。

6. 切换不同主题或卡片纹理

**预期**：实心圆、今天描边、文字和卡片背景均跟随主题，内容保持可读。

## 32. 今日页：当天日记闭环验证

1. 当天无生活片段、无日记时进入今日页

**预期**：“今日正在形成”卡片不显示日记操作，避免无内容时制造任务压力。

2. 新增一条片段，点击“整理成今日日记”

**预期**：自动切换到日记页并立即显示生成中状态，只发起一次生成；无需再次点击日记页的生成按钮。

3. 等待生成完成后返回今日页

**预期**：操作变为“今日日记已形成 · 去看看”；点击后直接打开对应日记详情。

4. 日记生成后再新增一条片段，返回今日页

**预期**：操作提示“1 个片段有变化 · 去更新日记”；点击打开现有日记详情，由用户决定是否重新生成。

5. 从当天记录中删除一条已被日记使用的片段

**预期**：同样提示片段有变化；若所有源片段都已删除，已有日记仍可正常查看，不提供必然失败的生成操作。

6. 快速重复点击生成入口，或在生成期间切换今日/日记页面

**预期**：不会并行生成多篇日记；生成进度、结果和错误提示在页面切换后保持一致。

## 33. 今日页：回来就好验证

1. 新安装且没有任何生活记录时进入今日页

**预期**：不显示“回来就好”，避免把首次使用者误判为回归用户。

2. 最近一条记录是今天或昨天时进入今日页

**预期**：不显示回归卡片，正常记录节奏不被打扰。

3. 最近一条记录距今天 2～6 天，且今天尚未记录

**预期**：“最近 7 天”统计保持可见，其下方出现“回来就好”临时反馈；文案说明不用补齐，不出现断签、失败或责备措辞。

4. 最近一条记录距今天 7 天以上或 30 天以上

**预期**：分别提示过去记录仍在，或“没有欠下的打卡”；不要求恢复连续天数。

5. 点击“回来就好”整张卡片

**预期**：输入框获得焦点并弹出键盘，可以直接输入，不跳转其他页面。

6. 保存当天第一条片段

**预期**：回归卡片立即隐藏；微回声、今日形成、本周足迹和日记闭环继续正常更新。

7. 数据中存在非法日期或未来日期记录

**预期**：这些记录不影响最近一次有效记录的判断，页面不崩溃。

## 34. 设置页：温和记录提醒验证

1. 更新安装后进入设置页，找到“温和记录提醒”

**预期**：开关默认关闭；记录较少时的基础时间显示 21:30；说明中明确“已记录不打扰”和“至少 3 个记录日后自动调整”；升级后不会擅自开启每日通知。

2. 点击提醒时间，选择虚拟手机当前时间之后 1～2 分钟，再开启开关

**预期**：时间选择后立即保存；Android 13 及以上在缺少通知权限时会先询问授权；拒绝授权后开关自动恢复关闭。

3. 确保今天没有生活片段，保持应用在后台并等待提醒（非精确节能闹钟可能有几分钟延迟）

**预期**：收到标题为“给今天留一句话”的通知；正文温和，不含断签、任务未完成或责备措辞；通知带有“写一句”操作。无论点击通知正文还是“写一句”，都会直接打开今日页、滚动到记录卡片、聚焦输入框并弹出键盘。

4. 分别在应用完全关闭、停留于回忆/日记页、以及已经停留在今日页时点击上述提醒

**预期**：三种状态都只打开一个今日页实例并聚焦记录框；不会停留在原分页，不会重复弹出页面。旋转屏幕或切换深浅主题后，不会无故再次抢占输入焦点。

5. 新增一条今天的生活片段，将提醒时间再次设到随后 1～2 分钟

**预期**：到时完全静默，不产生通知，也不调用 LLM 或语音播报。

6. 关闭提醒，将时间设到随后 1～2 分钟并等待

**预期**：旧闹钟已取消，不再出现通知。

7. 重新开启提醒后重启应用，再次进入设置页；条件允许时也重启虚拟手机

**预期**：开关和时间保持不变；应用启动和开机后都恢复下一次提醒；一天触发后会安排下一天，不会同日重复通知。

8. 准备至少 3 个不同日期的生活片段，让每天第一条都在相近时间；开启提醒并重启应用

**预期**：时间按钮显示“当前预计 XX:XX　基础 XX:XX”；下一次闹钟参考最近最多 21 个记录日的首条时间，取中位数并圆整到 5 分钟；多片段的某一天不会被重复加权；最早不早于 07:00，最晚不晚于 22:30。

## 35. 今日页：常驻统计与动态反馈位验证

1. 准备没有当天记录、最近一天仍在昨天以内的数据并进入今日页

**预期**：问候下方始终显示“最近 7 天”统计；没有临时反馈时，不额外显示空白的动态反馈卡。

2. 准备最近一次记录距今天 2 天以上的数据并重新进入今日页

**预期**：“最近 7 天”和每日次数仍然可见；其下方出现“回来就好”，点击卡片或“从一句话开始”可以聚焦输入框。

3. 新增一条文字或语音片段

**预期**：临时反馈卡立即从“回来就好”切换成“Echo 回声”的生成状态；生成完成后在原卡片内展示真实回声，不新增第二张临时卡；上方每日次数同步更新并始终可见。

4. 在微回声生成期间快速新增第二条片段，或删除当前对应片段

**预期**：焦点卡只追踪最新有效记录；旧请求不会覆盖新回声，删除后能够回落到下一个有效反馈，页面不闪退。

5. 记录完成后立即离开再返回，并在 30 分钟新鲜窗口结束后再次查看

**预期**：窗口内仍显示刚才的微回声；窗口结束后临时反馈卡自动隐藏，“最近 7 天”从始至终保持可见；旧回声仍可在记录详情中查看，不会丢失。

6. 切换主题、卡片纹理或旋转屏幕

**预期**：周统计与临时反馈的内容各自保持正确，纹理分别遵循“生活记录”和“回声”语义，文字可读且临时反馈最多只有一张。

## 36. 设置页：Echo 回声偏好管理

1. 先在今日页分别积累“有共鸣”和“不太像我”，再进入设置页

**预期**：“Echo 回声偏好”显示去重后的认可与拒绝数量；说明中明确入选示例在生成时会发送给已配置的 LLM。

2. 点击“清空 Echo 偏好”，先取消确认，再重新操作并确认

**预期**：取消时数据不变；确认后数量变为空状态，清空按钮禁用；原生活记录和已生成回声仍能在今日页、记录详情与往日回声中查看。

3. 积累多条不同主题的偏好，再新增一条主题明确的片段

**预期**：提示词优先选择正文关键词/中文词组、mood、tags 和来源更接近的历史实例，相关性相同时再选较新的；措辞高度相似的实例不会重复占用名额，整个选择过程不请求网络。
